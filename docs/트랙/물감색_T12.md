### 엔진 (`domain/paint_color.dart`, 순수 Dart)

- `colorOf(시간대, 날씨|null, 걷기/뛰기)` → 색 id 16개 중 하나(M1 v0.7 이름 그대로): 날씨가 비·눈·흐림이면 날씨 색, 맑음·모름(null)이면 시간대 색, 뛰기면 뒤에 `_run`. id는 스키마 v10.5 표(`dawn·morning·day·sunset·night·rain·snow·cloudy` + `_run`, 기본 `basic`).
- 그 순간 시간대 = 정령 지점의 그날 일출·일몰로 낸 하늘 섞임(`scene.sky` 키 구간)에서 더 가까운 단계 (`paintPhaseAt`, `momentColorAt`).
- 색: config v22 hex. 뛰기는 v22 `intensity.run` 계산식(판단 20). 값이 `{ "walk": "#..", "run": "#.." }`이면 그 hex를 쓴다(11/15 디자인 기획 모양, 모두 쌍이면 `intensity` 없어도 됨). 계절이 붙은 id(`autumn.sunset`)·`region.<id>`도 읽게 해 뒀다(`paintBase`, 2단계 자리).
- 방울 보상 `rollDrop(물감 길 id, 방울 번호)`: `paint|물감 길|방울|칸` 문자열의 hash(FNV-1a + murmur3 fmix32) → 0~1. 보상 표 확률을 차례로 쌓아 한 수로 고르고(한 방울에서 많아야 하나), 물감 통이면 양을 다른 수로 770~1,540 정수 m 고르게. 기기·판·다시 계산·백업 복원에 상관없이 같다. 시험은 무작위를 주입한다(M1 v0.7).
- 보상 표: config `paintDrop.rewards` 목록이 있으면 그것(지금 아는 kind는 `tube`뿐, 모르는 kind·확률 합 1 초과는 FormatException), **없으면 `paintColor.tube.chancePerDrop` 한 줄로 만든다**(지금 config에는 목록이 없다, 판단 8). 지름길 권 같은 새 아이템은 넣지 않았다.
- `paintSplit`(남은 m로 칠하면 고른 색 몇 m + 기본 몇 m), `tubesLeft`(가진 통 수), `paintedColorAt`(그 분에 칠한 색).
- `trailSegments(paintAt:)`: 물감 분마다 칠한 색을 받아 색이 바뀌면 물감 구간을 나눈다(`TrailSegment.colorId`). 안 주면 T9 그대로.

### 칠하기·통 받기 (`app/paint_service.dart`, `app/paint_trail_controller.dart`)

- 물감 길을 열면 그 물감 길에 지금 칠할 물감(고른 색이 남았으면 그 색, 아니면 `basic`)을 적고 날씨를 바로 묻는다.
- 열린 동안 이정표와 같은 센서 물감 길 거리(안드로이드 센서, iOS 메우기면 앞 센서 + 메운 health)를 `events.flushSec`(5초)마다 `PaintService.addPaint`에 넘긴다:
  1) 고른 색 남은 m를 늘어난 만큼 줄이고, 0이 되면 그 넘김 시각에 `colorEndUtc`를 적고 프로필의 고른 물감을 비운다(뒤는 기본, 걷는 중 알림 없음).
  2) 새로 넘은 방울(내림(전 ÷ 100) + 1 ~ 내림(지금 ÷ 100))마다 보상을 굴려 통이면 그 순간 색(시간대·날씨·뛰기)으로 보관에 더한다. 그 색 통이 999면 안 나온다.
  끝날 때(멈춤·도착)도 마저 넘긴다. 럭은 그대로다(물감 길 거리로 동기화가 센다, M1 v0.7 ⑨).

### 화면

- **걷는 중 방울**(`PaintDropLayer`): 그 순간 색을 곱한다. 통이 나오는 방울은 바로 뒤(오른쪽 18pt)에 같은 색 물감 통 32pt, 주우면 `+1 럭` 옆에 통 아이콘 24pt(토스트 없음). 그 색 통이 상한이면 통을 안 보인다. 방울·길 위 통은 시간대 보정 안, 글자·아이콘은 보정 밖.
- **지도**(`MapPainter`): 구간마다 칠한 색(`MapData.paintLineColors`, `paintLines`와 같은 차례·길이), 모든 물감 구간 아래에 잉크 25%를 방울보다 1pt 크게 먼저 깐다(16장 11/14 디자인 기획). `paintColor` 인자는 `palette`(config 색 표)로 바뀜.
- **배낭 물감 탭**(화집 네 번째 탭 `물감 n`, `ui/album/album_paints.dart`): 가진 색만(기본은 늘 맨 앞, 무제한이라 꼬리표 아래 줄 빈칸, 다 쓴 색은 안 보임), 소품 탭과 같은 선반 칸(`ItemCell`) 3열, 물감 통 56pt + 꼬리표 이름 / ‘쓰는 중’(테라코타·점선 고리) 또는 남은 거리 ‘1.2 km’(이끼). 누르면 바로 쓰는 중(확인 없음). 가진 색이 3개보다 많으면 위에 ‘최근’ 3칸(마지막으로 주운 차례), 그 아래 ‘모은 색’(기본 + 16색 차례, 접기). 걷는 중(물감 길이 열린 동안)에는 칸이 안 눌리고 ‘걷는 중에는 물감을 고르지 않아요’ 한 줄.
- 새 색 점: 처음 모은 색만, 물감 탭과 쉼터 배낭에. 물감 탭을 열면 지운다(M2~M6 Y).
- 도장 탭 이름을 `도장 n`으로 줄였다(캔버스 6-1 11/15, 탭이 넷이라).
- 그림: `assets/ui/`에 `ui_paint_tube_road_*`·`ui_paint_tube_icon_*`(지시서) 또는 `ui_paint_bottle_*`(캔버스 11/15 납품 이름)을 넣으면 그것을 읽어 색을 곱한다(`ui/common/paint_art.dart`). 없으면 코드로 그린 임시 튜브.

### 날씨

- **Functions `getWeather(lat, lng)` → `{ kind: clear|cloudy|rain|snow, at }`**(`functions/src/weather.ts`): 로그인 필수, 서버가 위경도를 기상청 격자로 바꾸고(`src/kma.ts`, 기술 설계서 v0.8), 격자 밖(한국 밖)·숫자가 아니면 `bad-point`. `weatherCache/{nx_ny}`에 `config/weather.cacheMin`(seed가 config.json `paintColor.weatherSource.cacheMin` 60을 넣음) 동안 둔다. 실황 강수 형태(PTY)가 비·눈이면 그것, 없으면 초단기예보 하늘 상태(SKY 4 흐림 → cloudy). 실패하면 `weather-unavailable`.
- **에뮬레이터는 기상청을 부르지 않는다**: 격자와 한국 시각의 시(時)로 돌아가는 가짜 날씨. `KMA_FAKE_KIND`를 함수 환경에 넣으면 고정(README). 비밀 값은 에뮬레이터가 아닐 때만 함수에 붙인다(`secrets: isEmulator ? [] : [KMA_SERVICE_KEY]`).
- 앱: `ServerApi.getWeather`, `PaintWeatherController`(`app/paint_providers.dart`): 물감 길을 열 때 바로, 그 뒤 `askMin`마다(지금 config에 없어 `cacheMin` 60분, 판단 11) 정령이 있는 지도 위 여정 지점으로 묻는다. 서버가 없거나(시험·서버를 끈 빌드) 만 14세 확인 전이거나 실패하면 null = 시간대 색. 날씨는 저장하지 않는다(통은 받은 순간 색으로 저장된다).

## 판단한 것 (다르면 말해 주세요)

1. **통 색 = 그 순간 색, 물감 길 = 고른 색**: 2장 표 ‘물감 통이 함께 나오고 그 순간 색으로 모임’·‘고른 색을 다 쓸 때까지 물감 길을 칠하고’, 캔버스 4-1 ‘노을 → 기본 두 구간’. 방울에 곱하는 색도 그 순간 색(캔버스 3-1 메모·Y).
2. **방울 번호 = 센서 물감 길 거리 기준**(걷는 중 화면의 방울·이정표와 같은 거리), 넘길 때 한 번 정하고 다시 계산하지 않는다(길 위 이벤트와 같은 방식). 동기화가 health 분으로 셈하는 trailM(럭·방울 수 표시)과 몇 개 다를 수 있다. 앱이 갑자기 끝나면 마지막 넘김(최대 5초) 뒤 거리는 칠하지 않는다.
3. **칠한 거리도 같은 센서 거리**, 다 쓴 시각 = 그 넘김 시각(5초 단위). 지도는 health 분을 그 시각으로 나눠 색칠해서 경계가 실제 쓴 m와 조금 어긋날 수 있다.
4. **물감 길 하나는 많아야 두 구간**(고른 색 → 기본): 걷는 중에는 고르지 않아서. 그래서 구간 색은 새 표 대신 `PaintTrails` 열 둘로 저장했다(스키마 v10.5 ‘trailSegments에 colorId 열’을 이렇게 읽음, trailSegments는 저장하지 않는 계산이라).
5. **통 수 = 아직 다 안 쓴 통**(주운 차례로 썼다고 센다). 999 상한도 이것 기준. 다 쓰면 0이고 줄은 남는다(배낭에는 안 보임).
6. **고른 색을 다 쓰면 고른 물감을 비운다**(기본으로). 그 색 통을 다시 주워도 저절로 다시 고르지 않는다(물을 것 2).
7. **보상 표는 한 방울에 많아야 하나**(확률을 쌓아 한 수). 나중에 특수 아이템 줄을 더해도 통 확률은 그대로다.
8. 보상 표를 config 목록으로 두라 했지만 **config를 고치지 않았다**(개발 기획 몫, data-v13 v23과 부딪히지 않게). 앱은 `paintDrop.rewards`를 이미 읽고, 없으면 v22 `tube.chancePerDrop`로 같은 목록을 만든다.
9. **흐림은 초단기예보로**: 초단기실황에는 하늘 상태가 없어 강수가 없을 때 같은 서비스의 초단기예보(SKY)를 한 번 더 부른다(명세는 ‘초단기실황’만, 같은 키). 비/눈 섞임(PTY 2·6)은 비, 구름많음(SKY 3)은 맑음, 흐림(4)만 cloudy(물을 것 1).
10. 격자 변환은 서버에서(기술 설계서 v0.8·Y `getWeather(lat, lng)`). 앱은 위경도만 보낸다. 개발 계획의 ‘앱은 … 기상청 격자’는 이렇게 읽었다. 격자 상수(지구 반경 6371.00877km 등)는 기상청 규약이라 코드에 뒀다.
11. **날씨 묻는 간격**: Y는 ‘30분마다’인데 config에 키가 없어 `cacheMin`(60분)을 쓴다. `weatherSource.askMin`이 생기면 그것.
12. 날씨는 로그인한 사용자만(스키마 v10.5 ‘인증 사용자만’) — 앱은 익명 로그인을 하고 부른다. 만 14세 확인 전이면 시간대 색.
13. 정령 지점을 모르면(출발 동네 전, 물감 길은 시작 흐름 뒤라 거의 없음) config `route.ports` 첫 항구 자리로 시간대를 잰다.
14. 배낭 ‘최근’ 3칸은 가진 색이 3개보다 많을 때만(적으면 ‘모은 색’과 같아서). 묶음 이름 ‘최근’·‘모은 색’은 가안. 계절·지역 묶음은 2단계에서 ‘모은 색’을 나눈다.
15. 걷는 중에 쉼터에서 배낭을 열면 물감 탭은 보이고 고르기만 막는다 + 한 줄 안내(가안, 물을 것 3).
16. 물감 통 그림 이름은 지시서(`ui_paint_tube_road`·`ui_paint_tube_icon`)와 캔버스 11/15(`ui_paint_bottle`) 둘 다 찾는다. 배낭 칸·머리 위는 아이콘, 길 위는 road 그림.
17. 도장 탭 이름 `도장 n`(캔버스 6-1 메모 11/15). 시험 하나(`road_event_ui_test` ‘도장 2’)를 고쳤다. T11이 화면 글을 볼 때 겹칠 수 있다.
18. 지도 테두리 1pt·잉크 25%, 통 32·24·56pt, 방울 뒤 18pt는 화면 구성값이라 코드에 뒀다(16장·지시서·캔버스 값).
19. 그 순간 시간대는 하늘 섞임에서 가까운 단계다(배지 `phases` 구간과 다르다, 물감 쪽 정의가 없어서 config 메모 ‘시간대 = scene.sky 키 구간’을 따름).
20. v22 뛰기 계산식: `darken` = 밝기에 (1 − 0.18) 곱하기, `saturate` = 채도에 0.15 더하기(가안 값이라 11/15 hex가 오면 안 씀).
21. 기상청 발표 시각: 실황은 정각 발표·40분부터, 예보는 30분 발표·45분부터 받을 수 있다고 보고 그보다 앞 시각을 부른다(기상청 활용 가이드). 응답 `at` = 실황 발표 시각.

3. 걷는 중(물감 길이 열린 동안) 쉼터에서 배낭을 열면 물감 탭은 보이되 고르지 못한다(판단 15). 이때 고르면 다음 물감 길부터 쓰게 할까?

## 개발 기획에 넘길 것 (2단계에 필요한 config 모양, 앱 코드는 아래를 기다림)

- **16색 hex(11/15 확정)·뛰기 hex**: `paintColor.timePhase.<시간대>`·`paintColor.weather.<날씨>`를 `{ "walk": "#C0ADE6", "run": "#A18AD0" }` 꼴로. 앱은 이미 읽는다(시험 있음). 모두 쌍이면 `intensity`는 지워도 된다(문자열이 하나라도 있으면 `intensity.run`이 필요). 눈 `#E4E9EE` → `#CEE7EC`(대비 1.01).
- **보상 표**: `paintDrop.rewards: [ { "kind": "tube", "chance": 0.1 } ]`(앱이 이미 읽음, 이게 있으면 `tube.chancePerDrop`은 안 씀). 새 kind(지름길 권 등)는 config 한 줄 + 앱 코드(받았을 때 무엇을 주는지)가 필요하다.
- **날씨 묻는 간격**: `paintColor.weatherSource.askMin: 30`(Y ‘30분마다’). 없으면 앱은 `cacheMin`.
- **계절 표**(제안): `paintColor.season: { "months": { "spring": [3,4,5], … }, "hex": { "spring": { "dawn": { "walk": "#…", "run": "#…" }, …16색 }, … } }`. `months`가 없으면 config `seasons`(봄 3~5 …)를 쓰면 된다. 보관 키는 `<계절>.<색 id>`(예 `autumn.sunset_run`), 이름은 앱이 ‘가을 진한 노을’로 만든다(앱에 이미 있음). 통의 계절 = 주운 날(한국 날짜)의 계절.
- **지역 색**(제안): `paintColor.region: { "chancePerTube": 0.15 }` + 권역 데이터 한 줄마다 `paintColor: { "id": "kr.capital", "name": "수도권 단청 주홍", "hex": "#EF937C" }`(나라 > 권역 두 단계, 캔버스 id `region.kr.capital`). 앱은 물감 통이 나오면 15%로 그 통을 ‘가장 가까운 명소의 권역’ 지역 색으로 바꾼다(한 방울에 많아야 하나 그대로). 지역 = `landmarks.json` region이면 7색은 그 7키로 맞춰 주면 된다.
- check_data: `colorCount`(16) 검사는 그대로 맞다. 계절 표가 오면 `4 × 16`·지역 7을 같이 보면 좋다.
- 디자인기획/물감색_개발인계.md·물감색_계절지역.md는 Claude 프로젝트 문서라 읽지 못했다 → 16장 줄·캔버스 값으로 했다. 배낭 묶음 이름·접는 기본 상태가 그 문서에 있으면 알려 주세요.

## 폰에서 볼 것

- 걷는 중: 방울 색이 시간대(아침·낮·노을·밤)로 바뀌는가, 뛰면 진한 색인가, 약 1km(방울 10개)에 한 번쯤 방울 바로 뒤에 물감 통(임시 그림), 주우면 ‘+1 럭’ 옆 통 아이콘. 밤에 방울·통이 정령처럼 어두워지는가.
- 배낭 → 화집 ‘물감’ 탭: 첫날 기본 한 칸 ‘쓰는 중’. 걷고 나면 통을 주운 색이 생기고 배낭·탭에 점, 남은 km, 누르면 바로 ‘쓰는 중’. 그 색으로 걸으면 남은 km가 줄고 다 쓰면 조용히 기본으로(알림 없음). 탭 넷이 작은 화면(375×667)·글자 크게에서 안 잘리는가, ‘도장 n’.
- 지도: 고른 색 구간 → 기본 구간으로 이어지는가, **연한 색이 종이 위에서 보이는가**(잉크 25% 테두리), 끝 방울.
- 날씨: 서버를 끈 빌드는 시간대 색만. 에뮬레이터에 붙인 빌드는 가짜 날씨(시마다 바뀜)라 비·눈·흐림 색이 나오는가.
- iOS: 화면을 끄고 걸은 구간도 켠 뒤 칠해지고 통이 나오는가(메운 거리로 센다).
