# T5 정령 메모리·성능 인계 (riv 한 번 읽기, 안 보일 때 멈추기, 누름 판정)

브랜치 `claude/t5-spirit-perf-33e4af`, 시작 `316621b`(dev-batch: T5 정리·T12 2단계·T6c·T11까지) 위 커밋들(끝은 이 노트).
push·dev-batch·main 합치기·릴리스 빌드·폰 설치는 하지 않았다. **DB·config·데이터 JSON은 안 바꿈**, 새 패키지 없음, `dart format` 안 씀. 화면 모양·자세·표정 동작은 그대로(성능·구조만).

**결론**
- ① riv 한 번 읽기: **끝.** 11.8MB `spirit_v36.riv`를 그리기(Factory)마다 한 번 읽어 모든 정령이 같이 쓴다(`SpiritFile`). 앱 기본 그리기는 `main()`에서 미리 읽어 앱이 끝날 때까지 둔다(계약 7장). 컨트롤러·아트보드·뷰 모델 인스턴스는 정령마다 따로다. 하루 카드 공유 이미지의 Flutter 그리기는 따로 읽고, 쓰는 정령이 없으면 전처럼 놓는다. 맥 참고값으로 한 벌이 약 150MB·0.65초(Flutter 그리기, 폰 값 아님)라, 정령 화면이 쌓일 때마다 늘던 몫이 없어진다.
- ② 안 보일 때 멈추기: **덮인 화면은 이미 멈추고 있었다**(Navigator가 불투명 화면 아래를 TickerMode 끔 → rive_native가 타이머를 멈춤). 그래서 코드를 더하지 않고 시험으로 묶었다. **앱이 뒤로 갔다 오면** 첫 프레임이 뒤에 있던 시간 전체를 한 번에 흘려보내던 것을 고쳤다(멈춘 자리에서 이음).
- ③ 누름 판정: **config 키가 모자라 코드 상자 그대로.** `headTopRatio` 0.45로는 지금 상자(경계 아트보드 55%, 좌우·위·아래 끝)를 못 나타낸다. 필요한 키 모양은 아래 ‘개발 기획에 넘길 것’.
- 폰(Z 플립6) fps·메모리·화면 오가기는 못 쟀다. 순서와 기대값은 아래 ‘폰에서 잴 것’.

## 판단 (다르면 말해 주세요)

1. **덮인 화면에 TickerMode를 새로 두르지 않았다.** Flutter `Overlay`가 불투명 화면(`MaterialPageRoute`·기본 `PageRouteBuilder`) 아래의 `maintainState` 화면을 `TickerMode(enabled: false)`로 감싸고(전환이 끝난 뒤), rive_native 0.1.11의 그리기 상자 둘(Flutter 그리기 `FlutterRiveRendererWidget`, Rive 그리기 `_RiveNativeView`)이 `TickerMode.of`를 읽어 타이머를 멈춘다. 다시 켜질 때 지난 시간을 0부터 잰다. 그래서 가장 단순한 방법은 ‘그대로 두고 시험으로 묶기’였다. 시험은 Flutter 그리기로만 돈다(시험 환경에 Rive 그리기 텍스처가 없음). Rive 그리기는 같은 `RiveRenderBox` 코드를 읽어 확인했다.
   - 계속 그리는 경우: 투명 화면(`opaque: false`)·아래 시트·대화 상자 밑, 같은 화면 안에 겹친 것. 정령이 비쳐 보이므로 움직이는 게 맞다. 지금 투명 화면은 하루 카드(노트 위, 노트에는 정령 없음) 하나이고, 쉼터 위 하루 카드는 쉼터 화면 안에 겹친 것(바탕 55% 어둡게)이라 쉼터 정령과 카드 정령이 같이 움직인다.
2. **앱이 뒤로 갈 때는 TickerMode로 못 끈다.** hidden·paused에서 Flutter가 프레임을 끄므로 `setState`가 돌아올 때까지 빌드되지 않는다. 그래서 컨트롤러가 직접 시간을 맞춘다(`setAway`). inactive(알림 창 내림·분할 화면)는 아직 보이므로 그대로 움직인다. 돌아온 첫 프레임 하나(보통 16ms)를 버리는 것이라 보이는 움직임은 같다.
3. **파일을 놓는 때**: 기본 그리기는 계약 7장대로 앱이 끝날 때까지 둔다(쉼터가 첫 화면이라 어차피 늘 있음). 다른 그리기는 빌린 정령이 0이면 dispose(전과 같은 메모리). 시험은 `main()`을 안 돌려 미리 읽지 않고, 시험이 끝나 정령이 다 사라지면 놓아 시험끼리 파일이 섞이지 않는다(`testWidgets`마다 가짜 시간 영역이 달라 덜 읽힌 Future를 넘기면 멈출 수 있음).
4. **미리 읽기 자리**: `startServer()`를 기다리기 전. 첫 화면 전 스플래시 동안 읽어 쉼터가 뜰 때 정령이 바로 보이게. 첫 화면이 늦어지는지는 폰에서 잴 것(아래 4).
5. **누름 판정은 안 바꿈**: config를 고치지 않는 조건이라 코드 상자를 두고 주석으로 이 노트를 가리켰다.

## 개발 기획에 넘길 것 (config `character.rive.hit`)

지금 앱 상자(11/12 통합본 그대로, 600 캔버스 → v36 아트보드 502×600으로 바꿔 계산, 뒤집기 전):

| | 600 캔버스 | 아트보드 px | 아트보드 비율 (x/502, y/600) |
|---|---|---|---|
| 머리 `tapHead` | x 200~400 · y 135~300 (경계 포함) | x 75.7~406.5 · y 58.2~331.1 | x 0.151~0.810 · y 0.097~0.552 |
| 배 `tapBelly` | x 230~380 · y 300 초과~445 | x 125.3~373.4 · y 331.1~571.0 | x 0.250~0.744 · y 0.552~0.952 |

- `headTopRatio` 0.45가 아트보드 기준이면 경계가 y 270(캔버스 263)이라 지금(331, 55%)보다 61px 위다. 몸 키 기준(머리 위 86 + 473.5 × 0.45)이면 y 299(50%). 어느 쪽이든 지금 앱과 다르고, 좌우·위·아래 끝은 키가 없다.
- 제안 키 모양(값은 지금 앱, 단위는 아트보드 비율):
  ```json
  "hit": {
    "approx": true,
    "unit": "artboardRatio",
    "head": [0.151, 0.097, 0.810, 0.552],
    "belly": [0.250, 0.552, 0.744, 0.952],
    "note": "x0, y0, x1, y1. 경계 y는 머리에 넣음. 뒤집기(flipSideOn)는 발 디딤점 x(244)를 축으로"
  }
  ```
  `headTopRatio`는 `head`의 y1과 같은 뜻이 되므로 지우거나, 0.45로 바꿀 거면 `head` y1·`belly` y0을 같이. 개발 기획이 정할 것: 경계 55%(지금) ↔ 45%(가안), 폰에서 누르기로 확인(계약 8장).
- 뒤집기: 지금 앱은 뒤집어도 상자를 안 뒤집는다(걷는 중 옆모습). 머리 상자가 거의 가운데라 차이는 캔버스 3.5px. 키가 오면 발 디딤점 축으로 뒤집어 읽는다.
- 자세별: 잠들기(4)는 몸이 y 237~458이라 머리 상자 위쪽은 빈 곳이다. config 글대로 자세별 실측이 오면 바꿈(미니 친구 `pet`도 그때).
- 키가 오면 할 일(개발, 약 0.1일): `spirit_character.dart` `onTapDown`의 숫자를 config에서 읽고 시험 하나.

## 통합 세션이 합칠 때

- 충돌 주의 파일:
  - `app/lib/ui/scene/spirit_character.dart`: `_SpiritCharacterState`의 `initState`·`_load`·`didChangeAppLifecycleState`·`dispose`, `preload` 정적 함수, `onTapDown` 주석 3줄. 다음 정령 판 교체(`asset` 줄)·누름 키 연결이 같은 파일을 고친다. `asset` 줄은 안 건드렸다.

  - 새 파일: `app/lib/ui/scene/spirit_file.dart`, `app/test/ui/spirit_perf_test.dart`.
- 다른 브랜치가 앱 코드에서 `rive.File.asset(SpiritCharacter.asset, …)`을 직접 부르면 `SpiritFile.acquire`/`release`로(시험 `spirit_runtime_test` 등이 직접 읽는 것은 일부러 따로 읽는 것이라 그대로).
- 새 정령 판(미니 친구·그림체 B안)으로 riv만 바꾸면 이 코드는 그대로다(파일 이름은 `SpiritCharacter.asset` 한 곳).

시험 환경(맥, 디버그 JIT, Flutter 그리기)에서 `File.decode`를 세 번 해 RSS를 쟀다. Rive 그리기는 시험 환경에 그리기 객체가 없어 못 쟀다.

| | 한 벌마다 |
|---|---|
| 읽기(바이트 → File) 시간 | 0.63~0.70초 (UI 스레드) |
| File RSS | +147~155MB (처음 한 번은 +222MB, 준비 비용 포함) |
| 정령 하나의 아트보드 RSS | +11~12MB |

→ 전에는 정령이 있는 화면이 쌓일 때마다(쉼터 아래 걷는 중·꾸미기 등) 한 벌씩 늘었고, 이제는 1벌 + 정령마다 아트보드뿐이다. 폰(Rive 그리기, AOT)에서는 그림이 GPU 쪽에 올라가 숫자가 다를 수 있어 ‘폰에서 잴 것’ 5·6으로 확인한다. Flutter 그리기 한 벌이 이만큼이면 하루 카드 공유 이미지를 뜨는 동안의 둘째 벌도 큰 편이다(전과 같음, 공유 뒤 놓음).
