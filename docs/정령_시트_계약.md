# 정령 컷아웃 데이터 계약 v0.2 (2026-11-06, 개발 기획)

근거: 16장 11/6 '정령 움직임 = 컷아웃 공정'(시트 방식 v0.1 대체), Codex 지시 `디자인기획/codex_spirit_cutout_v01.md` v01.3.
분담: Codex = 조각 그림 + `spirit_cutout.json` + `cutout_render.py`(정답 코드), 개발 = Flutter로 옮김·성능 확인·입자 효과.
이 문서는 Codex 지시서의 json 모양을 **앱이 읽는 계약**으로 고정하고, 앱에 필요한데 지시서에 없는 것(아래 ★)을 더한다.
★ 항목은 디자인 기획에 요청서로 넘겨 2차 지시에 넣는다(디자인/요청_대장.md). 1차 납품에 없으면 앱이 아래 '없을 때' 값으로 버틴다.
납품·Annie 검수 전까지 앱은 Rive v25 그대로(config character.anim `mode: cutout`, `file: spirit_cutout.json`, `pending: true`).

## 1. 한눈에

- 정령 = 조각 6개(head·torso·팔 2·발 2) × 방향 3(front·side·back, 왼쪽 = side 좌우 뒤집기).
- 포즈 = 클립의 키마다 조각별 `{dx, dy, rot, sx, sy}`. 그림은 방향마다 한 벌, 동작 수와 상관없음.
- 옷·신발·소매 = 조각과 같이 움직이는 덧층(조각 이름별 한 장). 모자·얼굴 소품·가방·장갑 = 조각 위 기준점(앵커)에 붙는 한 장.
- 몸 색은 조각의 `fill` 마스크에만 곱한다(얼굴·옷·외곽선에 안 묻음).
- 얼굴은 v24 파츠 그대로, head의 faceCenter에 `faceScale`·`faceOffset`으로 얹음. 뒷면은 얼굴 숨김.

## 2. 좌표·변환 (Codex 지시 2·6장과 같음)

| 항목 | 값 |
|---|---|
| 캔버스 | 1024×1024, 발 y 960, 가운데 x 512, 머리 꼭대기 ≈ 192 |
| 조각 원본 | 잘라 내지 않고 1024 캔버스의 서기 자리 그대로 → 6장 겹치면 서기 그림 |
| 회전 | 도, + = 시계방향(옆모습에서 + = 앞으로 숙임) |
| 변환 순서 | 자기 피벗 중심 sx·sy → rot → (dx, dy), 그 위에 부모 변환. root → torso → head·arm, 발은 root 자식 |
| 키 사이 | 직선 보간(앱이 ease를 더해도 됨) |
| 화면 키 | 세로 540px·가로 406px(config character.canvas) = 원본 × 0.703·0.529 |

앱 넣는 판: 내보낼 때 0.75배 + 투명 여백 자르기, 자른 자리 `trim: [x, y, w, h]`(1024 좌표)를 json 조각 항목에 더한다(개발 내보내기 스크립트가 씀, Codex 아님). 피벗·앵커는 1024 좌표 그대로.
메모리 추정: 한 방향 조각 6 + fill 6 + 옷 덧층 약 5장, 잘라 낸 0.75배 한 장 평균 0.3~0.5MB(추정) → 한 방향 약 6~9MB, 세 방향 모두 올려도 약 25MB. 시트 방식(v0.1) 대비 동작이 늘어도 그대로.

## 3. spirit_cutout.json (앱이 읽는 키)

Codex 지시 6장 예시가 기본. 앱은 아래 키만 읽고 나머지는 무시한다.

```json
{
  "version": 1, "canvas": [1024, 1024], "feetY": 960,
  "pieces":  { "<dir>": { "<pieceId>": { "file", "fill", "parent", "pivot": [x, y], "trim"? } } },
  "anchors": { "<dir>": { "<anchorId>": { "piece": "<pieceId>", "at": [x, y] } } },
  "face":    { "front": { "anchor": "faceCenter", "layout", "faceScale", "faceOffset": [dx, dy] }, "side": {…}, "back": null },
  "order":   { "<dir>": ["<층 이름>", …] },
  "specials":{ "<specialId>": { "<pieceId>": "<file>" } },
  "clips":   { "<clipId>": { "dir", "fps", "loop", "keys": [ { "<pieceId>|root": {dx, dy, rot, sx, sy}, "face": "<표정>", "special": null } ] } },
  "hit"★:   { "<dir>": { "head": {"piece": "head", "cx", "cy", "rx", "ry"}, "belly": {"piece": "torso", …} } }
}
```

- 조각 키에 없는 값은 0(dx·dy·rot)·1(sx·sy). 키 수가 다른 클립도 됨.
- `special`이 있으면 그 키 동안 해당 조각 그림만 바꿔 끼움(피벗은 원래 조각 것).
- 지시서의 제한(sx·sy 0.75~1.3, 팔 −160~+60°, 머리 ±15°, 발 y ≤ 960 점프 제외)을 앱 테스트로도 검사한다.

## 4. 앵커 (조각에 붙은 점, 조각과 같이 움직임)

| 앵커 | 조각 | 붙는 것 | 지시서 | 없을 때 |
|---|---|---|---|---|
| headTop | head | 모자(챙 아래) | 있음 | — |
| faceCenter | head | 얼굴 파츠, 얼굴 소품(안경·헤드폰·귀마개) | 있음 | — |
| neck | torso | (head 피벗) | 있음 | — |
| back | torso | 가방(큰 붓·배낭·봇짐) | 있음 | — |
| wristL·wristR (옆: wristNear·wristFar) ★ | 각 팔 | 장갑 덧층(`fit: wristOverlay`) | 없음 | 팔 조각 피벗에서 팔 아래 끝(가장 먼 불투명 픽셀)을 앱 내보내기 스크립트가 재서 씀 |
| petGround ★ · petShoulder ★ | root · torso | 미니 친구(소품 자료가 둘 중 하나) | 없음 | 땅: 발 옆 (x+260, 960), 어깨: neck (x+150, −40) |
| floatTop ★ | root | 둥실(머리 위 떠 있음, 머리 회전 안 따름) | 없음 | headTop 서기 자리 + (0, −120) |
| fx ★ | root | 효과 입자 시작점 | 없음 | 발 가운데 (512, 960) |

## 5. 손 소품 두 갈래 (props.json `fit`, v6)

- `wristOverlay`(장갑 hand_09·11·13): 방향·팔마다 장갑 한 장 `prop_<id>_<dir>_<wristL|wristR|wristNear|wristFar>_v01_clean.png` + `pivot`, wrist 앵커에 붙고 팔과 같이 돎. 가림 순서는 그 팔 바로 위.
- `replaceArms`(날개 팔 hand_10·12): 팔 조각 파일을 바꿔 끼움 `prop_<id>_<dir>_<armL|armR|armNear|armFar>_v01_clean.png`. 피벗·부모·클립 값은 원래 팔 그대로, `fill` 없음(몸 색 안 곱함). 날개 끝이 넓어도 회전 제한은 같음.
- check_data.py: 손 소품은 fit 둘 중 하나가 꼭 있어야 함.

## 6. 가림 순서 (층 이름)

지시서 order의 층 이름 + 앱 소품 슬롯 자리 ★. 비어 있는 층은 건너뜀.

- 조각: head·torso·armL·armR·armNear·armFar·footL·footR·footNear·footFar
- 덧층(조각과 같이 움직임): `clothBack`(망토 뒷자락) · `cloth` · `shoe`★(발 바로 위) · `glove`★(손목, 팔 바로 위)
- 앵커 층: `face`(얼굴 파츠) · `faceItem`★(face 바로 위) · `hat` · `bag` · `pet` · `float`★(맨 위)
- 앱 규칙: `shoe`·`glove`는 order에 따로 적지 않아도 해당 조각 바로 위에 그린다. `faceItem`·`float`가 order에 없으면 face 바로 위·맨 위.
- 소매(옷 덧층의 arm 조각)도 같은 규칙: 해당 팔 바로 위, 장갑보다 아래.

## 8. 색

- 몸 색: `fill` 마스크에만 palette body 색을 곱함(기준 밝기 200, palette v7).
- 색 소품(props material): 소품 덧층 조각마다 `neutral`(회색조) + `detail`(고정 무늬) 두 장, rgb = min(255, 회색 × hex ÷ 기준 밝기) 위에 detail. 기준 밝기는 props material(180, 베레모 192).
- 시간대 보정(config scene.tint char)은 정령 전체에.

## 9. 앱 쪽 (개발)

- `SpiritCutout` 위젯: CustomPainter 한 장. 키 보간 → 조각마다 Matrix4(부모 × 자기) → order대로 drawImageRect. fill은 saveLayer 없이 `ColorFilter.mode(multiply)` 페인트로 같은 변환에 그림.
- 표정·깜빡임: v24 규칙 그대로(face 층 교체, config character.blink).
- 누르기: hit 타원을 조각 변환으로 옮겨 판정. 없으면 head 조각 trim 상자 = 머리, torso = 배.
- 완료 기준: 중급 안드로이드에서 쉼터·걷는 중 60fps, 정령 이미지 메모리 +30MB 이하(추정 목표), 방향 바꿀 때 끊김 없음(세 방향 미리 읽기).
- 테스트: `cutout_render.py`와 같은 입력 → 같은 조각 변환 행렬(소수 3자리), 왼쪽 = side 뒤집기, 앵커 없으면 소품 숨김, 몸 색이 얼굴·옷에 안 묻음, replaceArms에 fill 없음, 제한 범위 밖 값이면 테스트 실패.

## 10. 디자인 기획에 넘길 것 (요청서)

1. hit(머리·배 타원), wrist·pet·float·fx 앵커를 2차 json에 넣어 달라(1차는 앱 기본값).
2. 소품 2차 파일 이름: 장갑 `_wrist*`, 날개 팔 `_arm*`(5장), 신발 `_foot*` 덧층, 얼굴 소품은 faceCenter 한 장 + pivot.
3. sleep은 lie_front + sleepy로, jump는 laugh로 대신(추천). 새 클립이 필요하면 디자인 기획이 정함.
