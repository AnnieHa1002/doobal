# 정령 시트 + 파츠 데이터 계약 v0.1 (2026-11-06, 개발 기획)

근거: 16장 11/6 '정령 움직임 방식을 전신 리깅에서 짧은 애니메이션 시트 + 독립 파츠 조합으로'(초안, 최종 승인 전).
분담: Codex = 그림 + 이 문서 모양의 배치·가림 순서 자료(`spirit_anim.json`), 개발 = 앱 연결·성능 검증·입자 효과 5종.
이 문서는 **그림이 아니라 자료의 모양**을 정한다. 승인 전 초안이라 Codex 납품이 다르면 이 문서를 고친다(개발 기획).
승인 전까지 앱은 지금 Rive v25를 그대로 쓴다(config character.anim.pending = true).

## 1. 한눈에

- 몸 = 동작 시트: 동작 11 × 방향 3(정면·옆면·뒷면, 왼쪽은 옆면 좌우 뒤집기) × 6프레임.
- 위에 얹는 것 = 독립 파츠: 얼굴(v24 원화 27장), 소품 37종 방향별 파츠, 색 소품은 회색조 + 고정 무늬 층.
- 프레임마다 **기준점(앵커)** 과 **가림 순서**를 자료로 받는다. 앱은 계산하지 않고 그대로 겹친다.
- 몸 색은 **몸 층에만** 곱한다(지금 Rive 임시 방식은 얼굴·소품까지 색이 묻음 → 이 방식으로 해결).

## 2. 좌표·크기

| 항목 | 값 |
|---|---|
| 원본 캔버스 | 1024×1024, 발바닥 y 960, 머리 꼭대기 y 192, 가운데 x 512 (9장 정령 캔버스 그대로) |
| 앱 넣는 판 | 0.75배(768×768 캔버스), 프레임마다 투명 여백을 잘라 `trim: [x, y, w, h]`(768 좌표)와 함께 |
| 화면 키 | 세로 540px·가로 406px(config character.canvas, 11/5) = 원본 × 0.703·0.529 |
| 자료의 좌표 | **원본 1024 좌표**로 적는다(앱이 0.75·화면 배율을 곱함) |

메모리 추정: 원본 그대로면 1024² RGBA 4MB × 198장 ≈ 800MB라 불가. 0.75배·잘라 내기면 한 장 약 0.8~1.2MB, 지금 보이는 (동작, 방향) 6장만 올리면 약 7MB + 파츠(추정). 앱은 (동작, 방향) 묶음 단위로 읽고 최근 3묶음만 남긴다.

## 4. 앵커 (프레임마다)

모든 앵커: `{x, y, rot(도), scale, visible}`. 없으면 visible false로 본다.

| 앵커 | 붙는 것 |
|---|---|
| faceCenter | 얼굴 묶음 기준점. 눈·눈썹·코·입 위치는 v24 `face_asset_layout_v24.json` 상대값을 이 점에서 rot·scale과 함께 |
| headTop | 모자(챙 아래가 이 점), 둥실(위로 떠 있음) |
| ear | 얼굴 소품(헤드폰·귀마개·안경은 faceCenter) |
| body | 옷(일체형) 기준점 |
| handL · handR | 손 슬롯(장갑은 손 위, 날개는 팔 대신 → `hideArms` 표시) |
| footL · footR | 신발 |
| back | 가방(큰 붓·배낭·봇짐) |
| pet | 미니 친구(땅·어깨 높이는 소품 자료가 정함) |
| hitHead · hitBelly | 누르기 영역 `{cx, cy, rx, ry}` 타원(머리·배 누르기, 화남 연타) |
| fx | 효과 입자 시작점(앱 입자, 그림 없음) |

## 5. 가림 순서

방향마다 기본 순서 1줄 + 동작·프레임마다 바꾸는 것만 덮어쓴다.
예(옆면 기본): `back`(가방) → `armFar` → `body` → `cloth` → `shoeFar` → `shoeNear` → `face` → `faceItem` → `hat` → `armNear` → `hand` → `pet` → `float`.
몸 시트가 팔을 따로 그리면 armFar·armNear는 시트 안 별도 층 파일로 받는다(손 슬롯이 팔 사이에 끼기 위해). 못 나누면 '손'은 몸 위 한 층으로.

## 6. 소품 파츠

- 파일 이름: `prop_<id>_<front|side|back>_<piece>_v<NN>_clean.png`(정적 데이터 스키마 v6.1 규칙에 piece를 더함, 신발은 piece l·r).
- 파츠마다 `pivot: [x, y]`(앵커에 맞춰지는 그림 안 점, 원본 1024 좌표 기준 크기).
- 동작에서 모양이 달라지는 것(눕기·넘어지기의 옷·신발 각도 등)은 `override: {motion: {frames: [..], file}}`로 그 동작용 그림을 따로 받는다.
- 색 소품 7종: `neutral`(회색조)·`detail`(고정 무늬) 두 장 + props.json material.hex(기준 밝기 180, materials_v07과 같음).

## 8. 앱 쪽 (개발)

- 정령 위젯: (동작, 방향, 프레임) → 몸 프레임 + 앵커에 파츠를 겹쳐 그림(CustomPainter 한 장). 몸 층만 몸 색 ColorFilter → 그 위 얼굴·소품 → 시간대 보정은 전체에.
- 표정: 얼굴 층 교체(v24 표정 규칙 그대로), 깜빡임은 눈 층을 감은 눈으로(config character.blink), 뒷면은 얼굴 숨김.
- 누르기: hitHead·hitBelly 타원, 연타 화남(config character.tapReaction).
- 성능 확인(완료 기준): 중급 안드로이드에서 쉼터·걷는 중 60fps, 걷는 중 이미지 메모리 +30MB 이하(추정 목표), 동작 바꿀 때 끊김 없음(다음 묶음 미리 읽기).
- 테스트: 앵커 없는 파츠 숨김, 왼쪽 = 옆면 뒤집기, 가림 순서 덮어쓰기, 몸 색이 얼굴·소품에 안 묻음.
