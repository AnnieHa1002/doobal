## Annie 결정이 필요한 것

1. **금칙어 정답지와 앱의 차이.** Python은 `\w`·`\b`가 한글을 포함하고 Dart·JS는 아니다. `두발.com`, `한글아이디@한글.com`은 Python만 막고 앱·서버는 통과. 반대로 `아abc.com요`는 앱·서버만 막는다. 서버는 앱과 같은 쪽으로 맞췄다. 한글 도메인·메일까지 막으려면 moderation.json D2·E2 정규식을 고치는 것을 추천(앱·서버 함께 반영됨).
2. **닉네임 금칙어 없음.** 앱 닉네임 입력에 검사가 없고, 닉네임은 글과 함께 모두에게 보인다. 추천: 앱 닉네임 입력에 같은 검사를 넣고 서버 postGuestbook도 닉네임을 검사.
3. **프로토타입 5-2의 아바타 색·‘동행과/혼자’.** 서버 저장 항목에 없어서 넣지 않았다. 쓰려면 저장 항목(개인정보처리방침과 연결)을 먼저 정해야 한다. 추천: MVP는 빼고 닉네임·시간만.
4. **(11/6 처리) 카카오 연결 해제.** M6은 ‘Auth unlink만’이라 적었지만 카카오는 kakaoLinks 문서라 unlink로 끊기지 않아, Annie 허락으로 `kakaoUnlink`를 더했다(kakaoLinks만 삭제, 서버 기록은 그대로). 남은 일: 11/4 캔버스 설정에는 ‘계정 연결’만 있어 해제 버튼과 안내 문구는 앱 트랙에서 정한다.

## 명세에서 판단한 곳 (그대로 두면 됨, 다르면 말해 주세요)

- 읽기는 M5 ‘Firestore 직접 조회’ 대신 지시대로 Callable. 내 글은 빼고 줌(캔버스 ‘다른 사람 글 읽기’). 출력에 uid·rand·신고 수 없음.
- 캔버스에 맞춰 더한 것: `react`의 `kind: null`(하트 취소), `readGuestbook`의 `total`(‘2,418명 중 5명’). total은 글 수이고 내 글 포함.
- 프로토타입은 하트·신고가 따로 켜지지만 서버는 설계대로 한 값(reactions/{uid}). 신고하면 내 하트가 빠진다.
- 보안 규칙을 지시보다 좁힌 곳: `users`의 banUntil·deleteCount는 본인도 못 고치고 문서 삭제 금지(안 그러면 제재를 스스로 풂). 숨긴 글은 쓴 사람만 직접 읽음. reactions는 직접 읽기 금지(`counted`가 보이면 ‘표시 없이’가 깨짐). 직접 읽기를 아예 닫아도 되지만 지시대로 로그인 읽기를 두어 uid는 직접 조회로 보인다.
- 제재: 3번째 삭제부터 삭제마다 다시 7일(‘3이면’은 4번째를 말하지 않음). 7일은 한국 자정이 아니라 정확히 168시간. 하루 기준(KST)은 금칙어 통계 문서에 씀.
- 검토: 관리 화면이 없어 콘솔에서 `reviewQueue/{id}.decision`을 `delete`·`restore`로 바꾸면 트리거가 처리하고 대기열 문서를 지움. 복구한 글은 내용이 안 바뀌므로 다시 자동 숨김 안 함. 자동으로 숨김이 풀리지는 않음(하트가 늘어도).
- 카카오 합치기: M5는 ‘처음이면 지금 uid에 연결(옮길 것 없음)’, 설계서·지시는 ‘백업 이전’. 처음 연결은 M5대로, ‘이미 다른 uid에 연결’ + 확인했을 때 익명 uid의 서버 기록을 그 계정으로 합침. 글·반응 이전(같은 기회 글은 그 계정 것 유지), 백업은 그 계정에 없을 때만 이전, 제재는 삭제 횟수 합·늦은 제한, 익명 Auth 삭제. 구글·애플·다른 카카오에 연결된 계정은 합치지 않음.
- App Check: 명세대로 배포 환경 강제, 에뮬레이터는 끔. 앱에 붙이기 전 배포하면 Callable이 모두 거절된다.

## 앱 연결 트랙이 알아야 할 것

- 앱이 `users/{uid}`를 만들고 `nickname`·`totalSteps`를 올려야 한다(`createdAt`은 서버 시각만). 없으면 글 거절(`no-profile`), 신고가 셈에서 빠짐.
- `already-exists`는 재전송이면 보낸 것으로 처리. 오류는 `details.reason`으로 나눔(README 표).
- 설정 문서는 `npm run seed`로 넣는다. 없으면 글을 받지 않는다(INTERNAL).
