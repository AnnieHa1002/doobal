# 계정 삭제 뒤 수레 줄이 다시 생기는 경합 (11/23)

시작 dev-batch `013ac4e`. `settings_screen_test` ‘끝까지 가면 DB가 비고 설정·쉼터를 닫아 환영 화면이 나온다’가 가끔 깨지던 것.

## 결론

앱에서도 생기는 경합이었다 (시험만의 순서 문제 아님). 데이터 쪽에서 막았다.

## 원인

1. 설정 `_deleteAccount`가 `deleteAllLocal()`(한 트랜잭션으로 모든 표 비움) 뒤에 `snapshotProvider`를 invalidate 한다.
2. 그때 쉼터는 설정 화면 아래 경로로 아직 살아 있고, 쉼터 수레(`CartWithItemsArt`·`shopCartSlotProvider`)가 `todayCartProvider`를 본다.
3. `todayCartProvider`가 snapshot을 따라 다시 돌아 `todayCart()`를 부르면, 빈 DB라 그날 줄이 없어서 `_decideCart`가 `shop_cart_slots` 3줄과 `shop_shown`을 새로 넣는다. 프로필이 지워져 씨앗은 `''`.
4. 시작 관문이 환영 화면으로 바꿔 쉼터가 사라지는 것이 먼저면 안 생기고, 수레 계산이 먼저 DB에 닿으면 생긴다. 그래서 가끔.

앱에서의 영향: 지운 뒤 같은 수레 날(새벽 5시 전)에 다시 시작하면 첫 수레가 새 설치 번호가 아니라 빈 씨앗으로 정해져 있고, 나온 횟수(`shop_shown`)도 먼저 1이 적혀 있다. ‘이 기기의 기록이 모두 지워져요’와도 어긋난다.

재현: 고치기 전 dev-batch에서 파일 전체 1번 중 1번, ‘계정 삭제’ 묶음만 6번 중 1번 실패. 실패 값은 `shop_cart_slots`에 `2026-11-18` 3줄(shoe_01_c2·shoe_01_c1·shoe_06).
