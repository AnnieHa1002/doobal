## 크기

- PNG 66장 1,953,429바이트 → `tools/to_webp.py --write --remove-png`(장마다 ssimulacra2 ≥ 85·butteraugli ≤ 0.75로 고름) → **WebP 696,472바이트(약 680KB)**. 43장 손실(q80 10·q82 7·q85 7·q88 13·q90 6), 23장 무손실(무손실이 더 작거나 q95도 기준을 못 넘은 그림: 신발 8·베레모 3·망토 2·벙어리장갑·잎 장갑·돌하르방 등). 투명도는 모두 무손실.
- 늘어난 앱 그림: **696,472바이트(약 0.66MB)**. assets 폴더 69,543,921 → 70,240,393바이트(약 1.0% 늚). WebP는 앱 묶음에서 더 압축되지 않아 내려받기 크기도 거의 같게 는다(추정).
- 해상도는 받은 256×256 그대로. 칸은 64pt이고 `ItemImage`가 `cacheWidth` 192px(3배 화면)로 풀어 메모리는 192²만 쓴다. 192로 줄여 넣으면 파일이 대략 절반 남짓으로 줄 것(추정, 재지 않음)이지만 `to_webp.py`는 크기를 바꾸지 않고(규칙: 다듬기·자르기 안 함) 쉼터 수레 위 아이콘은 `cacheWidth` 없이 256으로 푼다(28pt라 작음, 한 장 256KB 이하·최대 6장). 그대로 둠.

## 판단

1. **파일 이름을 칸 그림 규칙에 맞춰 바꿔 넣었다**(`item_<id>_icon_v01_clean.webp`, T4b 노트·`asset_index.dart` 주석의 예와 같은 꼴). 받은 이름(`item_beret_v01`)에는 id가 없어 그대로는 안 잡힌다. 개발 계획 4장 ‘소품 아이콘 60’ 줄은 ‘props `icon`을 먼저 보고 없으면 id 이름 파일’이라 적었지만, 코드를 고치지 않고 이름만 바꾸는 쪽을 골랐다(이번 일 지시, 찾는 규칙 하나로 유지). 다시 뽑은 v02가 오면 `item_<id>_icon_v02_clean.webp`로 넣으면 새 버전이 먼저 잡힌다(`_rank`).
2. **WebP로 바꿨다**: 칸 그림 규칙이 `.webp`·`.png` 둘 다 받고 WebP를 먼저 고른다. PNG는 리포에 남기지 않았다(원본은 Drive).
3. **256px 그대로**(위 ‘크기’).
4. **색 소품 칸은 색 상자 대신 그림**이 된다(T4c 규칙 그대로, 코드 안 고침).
5. **id가 겹칠 위험**: 찾는 규칙이 `(^|_)<id>(_icon)?(_vN)?(_clean)?.(webp|png)`라 `evt_pet_01` 아이콘(`item_evt_pet_01_icon_…`)이 생기면 `pet_01`로도 잡힌다. 지금은 `evt_pet_*`가 pending이라 앱이 읽지 않고 아이콘도 없다. 이벤트 소품 아이콘을 넣을 때 확인.

## 데이터 제안 (개발 기획에 넘김, 값은 안 고침)

1. **props.json `icon` 값**: 지금 Drive 납품 이름(`item_beret_v01`)이고 앱은 이 값을 읽지 않는다(이름에 id가 든 파일을 찾음). 앱에 넣은 이름(`item_hat_01_icon_v01_clean`)으로 바꾸거나, ‘Drive 원본 이름’이라고 note를 달지. 다시 뽑을 때 납품 이름에 소품 id를 넣어 주면 바꿔 넣는 일이 없다(개발 계획 7장에 이미 적힌 요청).

3. **`float_04` 물빛 구슬 아이콘**: props `icon` = `ui_icon_float_04_v01`. 납품 때 `item_float_04_icon_v01_clean`처럼 이름에 id를 넣으면 파일만 넣어 끝난다.
