## 2. 입력 (모두 뷰 모델 속성, 상태 머신 입력 아님)

| 속성 | 값 | 앱이 넣는 곳 |
|---|---|---|
| poseChoice | 0 둥둥 정면 · 1 둥둥 옆 · 2 앉기 정면 · 3 앉기 옆 · 4 누운 잠들기 · 5 둥둥 뒤 · 6 옆 이동 | 3장 화면별 자세 |
| eye 1~6 · brow 0~6 · nose 0~7 · mouth 1~8 | riv는 넷 다 0 = 없음을 받지만, 앱은 눈썹·코만 없음을 보냄(눈·입 없음 칸 없음) | 모습 얼굴(palette `customPartsV33`) |
| exprDraft | 0 가안 A · 1 가안 B(v33 새 입력, 표정 그림 시안 고르기) | 앱은 늘 0(디자인 기획이 B로 정하면 config 한 값) |
| expr | 0 기본 · 1 행복 · 2 놀람 · 3 울먹임 · 4 졸림 · 5 화남 | 4장 |
| 트리거 | greet · joy · tapHead · tapBelly · angry · resetMotion | 4장 |
| 소품 Choice | hatChoice 0~4, faceChoice 0~3, cloth·shoe·hand·bagChoice 0~5, petChoice 0~13(v11, 6~13 상점 미니 친구), floatChoice 0~6(v11, 6 물빛 구슬) (0 = 안 입음). v36 hatChoice 5 새싹·6 꽃은 안 보냄(props·config `unusedChoices`, check_data가 막음) | 모습 슬롯(props `rive.n`) |
| 색 | bodyColor + 소품 37개 `<이름>Color` + 친구 8개(v11) = 46개를 앱이 넣음. 부분색 32개(v11, Trim·Inner·Lining·Detail·Pants 등)는 앱이 넣지 않음 | 몸 색·소품 색(5장) |

- 자세는 poseChoice만 바꾸면 riv가 전환한다. 앱이 두 그림을 겹쳐 흐리기 하지 않고, 같은 인스턴스를 계속 쓴다(입력 값이 이어짐). 0.15 재생기에서 어긋나면 `Pose_<n>_stable` 클립을 직접 적용(v0.11).
- 옆모습(1·3·6)은 왼쪽을 본다. 오른쪽으로 걷는 걷는 중 화면에서는 좌우 뒤집기(config `flipSideOn`).
- 다리 달랑·작은 움직임(숨쉬기·팔 톡·눈썹 들썩·고개 갸웃·깜빡임)은 riv 몫이라 앱 입력 없음.

## 2-1. 미니 친구 (16장 11/15, v11에 들어옴)

- 미니 친구(petChoice 1~13)는 riv 안에서 정령 poseChoice·expr·트리거를 그대로 따른다: 쉼터 앉기(2)·옆 앉기(3)·걷는 중(6, 옆 걷기 6프레임)·밤 자기(4·expr 4)·기쁨(joy)·화남(angry). 종이새·갈매기·떠 있는 상점 친구는 떠 있는 판(앉기 = 떠 있기, 자기 = 떠서 졸기). 앱 입력 추가 없음.
- (v0.11) 새 트리거 `tapPet`은 만들지 않음 — 친구 고유 반응은 riv 안 pointerDown 1.5초(v11 inputs.md). 앱은 누름을 riv에 그대로 넘김(정령 위젯 히트 테스트 그대로).
- 누름 판정: 미니 친구 자리 상자(자세별)는 v11 qa에서 실측해 config `character.rive.hit.pet`에 넣음(개발 T17, 폰 확인). 그전엔 쉼터·꾸미기에서 정령 몸 누르기 그대로.
- 크기: 정령 키의 약 25% 그대로(Annie 11/15, 떠 있음 약 82px·땅 108px — 검수 A25).
- 그림체 B안(갈색 외곽선·수채 결·볼 터치)은 그림만 바뀌고 입력·아트보드·원점은 그대로가 조건. 바뀌면 계약 다음 판.
- riv 용량이 늘어남(뼈·상태 추가): 개발이 받으면 크기·메모리 다시 잼.
- 걷는 중 옆 걷기 6프레임도 7장 빠르기 배율을 같이 받는다(같은 인스턴스라 따로 할 일 없음).

## 5. 모습 → 입력

- 얼굴: 저장값 id(e1~e6, none·b1~b6, none·n1~n7, m1~m8) → rive 번호. 기본 얼굴 e1·b1·n7·m7. 옛 v24 얼굴 값은 기본 얼굴로 초기화(출시 전, DB 버전 올림).
- 몸 색: palette body 견본 hex(또는 직접 고른 hex)를 bodyColor에 그대로. 색 계산(밝기 기준 등)은 riv 안이라 앱은 hex만 넘김.
- 소품: props.json v10 `rive` = {choice, n, color}. 슬롯마다 `<choice>` = n(안 입으면 0), 그 소품 색을 `<color>`에. color가 null이면(물빛 구슬) 색을 넣지 않음. 색 소품(variantOf)은 기본 소품과 같은 n + 자기 material.hex. 그 밖의 소품은 riv 기본 색 그대로(앱이 넣지 않음).
- (v0.11) 옷 기본색은 v11 riv 기본값과 같게 맞춤 — 앱 기본색이 riv 값을 덮어 보정색이 사라지지 않게(Codex 패치: 별밤 망토 #7B6885·여행복 #C0A475·금빛 코트 #D7B66C, 친구 5종도 v11 값). 부분색 32개는 앱이 안 넣음.
- 여행복 = clothChoice 4, 시작 색 4(카키 #C0A475·크림·살구·라벤더 #D3C6E6)는 travelVestColor에 그대로. 앞치마(300km)는 받을 때 한 색 고정(16장 11/16 ①, material.hex 그대로, 무작위 아님).
- 효과 슬롯(effect)은 Rive 밖, 앱 입자(CustomPainter, codex_effects_v01 조각).
- 번호·색 이름의 출처: 번호는 소품 아이콘 README 순서, 색 이름은 영어 이름 camelCase + Color. **11/13 v33 대조 끝**: 색 속성 38개 이름이 props와 모두 같고, runtime_inputs.json의 색 속성 순서(슬롯마다 1→5)와 기본값 clothChoice 4 = travelVestColor가 RIVE_ORDER와 같음 → props `rive.riveVerified true`. **11/20 v11 대조 끝**: 친구 Color 8개 이름이 props pet_06~13과 같음, floatChoice 6 = float_04. 번호마다 그림이 맞는지는 개발이 화면으로 한 번 확인.
- 옷 색 식(neutral × 색 ÷ 180 → ÷ 200, 11/11 디자인 기획 질문)의 답: 앱은 식을 쓰지 않고 hex만 넘긴다. riv 안의 기준값을 200으로 할지는 디자인 기획이 정하면 됨(개발 기획 쪽 제약 없음, 견본과 같아 보이는 쪽 추천).

## 6. 크기

- 정령 키 = 동행 키 × 0.75(16장 11/9, 그대로). 동행 Rive v15 크기는 그대로.
- 화면 배율 = (동행 화면 키 × 0.75) ÷ 몸 키. 몸 키(v36 계산값, 실측 전): v33 실측 y 71~559 = 489px(자세 0·여행복·소품 없음)에 v35 변환(가운데 (251,300) 기준 ×0.97, +8px)을 적용 → y 86~559 = 약 474px, 폭 x 105~384. 모자·떠 있는 소품은 키에 안 넣음. 아트보드 높이 = 몸 키 × 1.266(600 ÷ 474). 동행 화면 키 추정 459px(세로, 540 × 0.85) × 0.75 = 344px → 배율 344 ÷ 474 = 0.726, 아트보드는 화면에 364×435px. 가로 259 ÷ 474 = 0.546 → 274×328px. (11/15 개발 실측 473.5px, config `bodyBox.measured` true. 동행 키를 실측하면 `screenScale` 다시 계산. v11은 몸 그림이 같다고 보고 그대로 쓰되, 정식 판이 오면 한 번 다시 잼)
- 땅 맞추기: 발바닥 가운데 (244, 559) = 아트보드 (48.6%, 93.2%) 점을 길·갑판·쉼터 발 디딤 자리에 둔다(config `bodyBox.footAnchor`). 가운데 50%에 맞추면 6px 오른쪽으로 쏠림. 누운 잠들기(4)는 몸이 y 237~458이라 같은 기준이면 조금 떠 보임 — 폰에서 보고 정함.
- 소품을 많이 입으면 아트보드 거의 끝까지(x 2~500·y 3~597) 차므로 잘라 그리지 않는다.
- 떠 있기 높이·그림자·앉기에서 그림자 붙음은 riv 몫(앱 lift·그림자 타원 없음).
- 쉼터 자리(camp_wide `characterFloat` 가안 115pt)·배 위·이야기 그림 배율은 같은 몸 키로 다시 계산. 쉼터 꾸밈 물품을 못 놓는 자리는 이 상자(camp_wide v4 decor.blocked).
